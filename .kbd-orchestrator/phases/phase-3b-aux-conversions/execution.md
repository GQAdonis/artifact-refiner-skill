## Decisions during execute

1. **Templates renamed `.svg` → `.html`** for template-forge's `path_loader` compatibility. The Minijinja engine only looks for `.html` files; SVG-content-in-`.html`-file is semantically fine.

2. **`refine-moodboard` writes a synthetic brand TOML to a temp directory** for non-branded moodboards. template-forge needs a brand registry; we satisfy that by emitting the LLM-synthesized spec as TOML and pointing template-forge at the temp library. Avoids adding a `--data` flag to template-forge.

3. **`design-svg-logo` does PNG export only for variants × sizes that make sense** — icon at all sizes; wordmark/lockup only at sizes >= 128 (smaller would be unreadable text).

4. **LLM SVG fallback is per-variant, not per-run** — if the LLM produces a valid icon but invalid wordmark, the icon stays LLM-generated and the wordmark falls back. Each variant is independent.

5. **Markdown frontmatter overrides CLI flags** — `document-type: brief` in frontmatter wins over `--document-type article`. Gray-matter handles both YAML and TOML frontmatter.

6. **Moodboard motif/tone content is currently template-static** — the `moodboard.html` template has hardcoded motif descriptions and tone chips. The LLM-synthesized spec includes them in the JSON shape, but the template renders the templated ones instead. Documented as v2 follow-up (template needs to consume the spec's `motifs` and `tone` arrays).
